# Document istoric v43.1 — pentru instrucțiunile curente vezi README.md

# SongApp v43.1 · versiunea 0.3.1

Bibliotecă de cântări și pregătirea programelor bisericii.

## Pornire pentru utilizarea zilnică

Deschide `PORNESTE-APLICATIA.cmd` din folderul aplicației sau rulează:

```powershell
Set-Location "D:\Apps\song.app"
npm run local
```

Această comandă folosește versiunea optimizată. Compilează doar dacă sursele,
configurația sau `.env.local` s-au schimbat; altfel pornește direct serverul.
Compilarea inițială poate solicita procesorul temporar. După pornire, lasă
terminalul deschis și folosește `http://localhost:3000`.

`npm run dev` rămâne pentru modificarea codului: compilează paginile la accesare
și urmărește fișierele. Nu îl folosi pentru utilizarea zilnică.

### Actualizare v43 → v43.1

Oprește aplicația cu Ctrl+C, extrage pachetul peste surse păstrând `.env.local`, apoi:

```powershell
Set-Location "D:\Apps\song.app"
npm ci
npm run local
```

Nu este necesară o migrare SQL nouă pentru v43.1. Baza existentă rămâne aceeași.

## Actualizarea instalării tale existente (v42 → v43)

**Rămânem pe același proiect Supabase, cu aceeași bază de date.**
Nu crea un proiect nou și nu rula `supabase/setup/INSTALL-NEW.sql` pentru această actualizare.

1. Oprește aplicația și workerul, dacă sunt pornite, cu `Ctrl+C` în ferestrele lor PowerShell.
2. Păstrează o copie de siguranță a surselor și bazei. Extrage pachetul peste `D:\Apps\song.app`. Păstrează fișierul tău `.env.local`.
3. În Supabase → proiectul existent → SQL Editor → New query, rulează conținutul fișierului **supabase/updates/UPDATE-V43.sql** din folderul supabase/updates. Aceasta este singura actualizare SQL necesară dacă ai aplicat deja v42.
4. În PowerShell:

```powershell
Set-Location "D:\Apps\song.app"
npm ci
npm test
npm run build
npm run local
```

5. Deschide `http://localhost:3000/import` și folosește fila **Din link**.

**Workerul nu mai trebuie pornit.** Importul unui link se execută la apăsarea butonului „Citește linkul”; salvarea se face doar după confirmarea preview-ului.

Dacă încă nu ai aplicat v42, aplică mai întâi `supabase/updates/UPDATE-V42.sql`, apoi `supabase/updates/UPDATE-V43.sql`, în aceeași bază existentă.

## Noul flux de import

1. Adaugă linkul unei cântări Resurse Creștine și apasă **Citește linkul**.
2. Verifică titlul, versurile și informațiile sursei. Poți corecta textul înainte de salvare.
3. Bifează una sau mai multe dintre colecțiile existente.
4. Opțional, completează numărul în colecții, ordinea interpretării și notele.
5. Apasă **Salvează cântarea în colecții**.

Preview-ul nu creează cântări sau colecții și nu schimbă baza bibliotecii. La salvare se creează cântarea, secțiunile și legăturile cu colecțiile într-o singură tranzacție. Legătura la sursă și autorul sunt păstrate. Importurile noi intră în fluxul obișnuit de verificare a versurilor.

Dacă același link a mai fost importat, aplicația reutilizează cântarea existentă, păstrând editările locale. Pentru titluri identice sau foarte asemănătoare, preview-ul arată opțiunea de a folosi cântarea existentă. Repetarea salvării aceluiași link nu creează o copie suplimentară.

Fila **Din fișiere** păstrează importul PPTX/PDF/TXT/ZIP. Fila **Din text** păstrează adăugarea manuală. Schimbarea filelor nu șterge preview-ul cât timp rămâi în pagina de Import.

## Cântările importate anterior și sincronizarea veche

Cântările, colecțiile, fișierele și referințele existente rămân în baza de date. Migrarea v43 anulează doar rulările de sincronizare încă în așteptare sau în lucru; nu șterge cântări.

Pagina Surse externe este ascunsă din meniu, iar accesul direct redirecționează spre Import. Pornirea noilor loturi este dezactivată implicit. Codul și tabelele vechi rămân pentru o eventuală revenire ulterioară.

Variabila privată `ENABLE_EXTERNAL_SYNC=true` permite reactivarea instrumentelor vechi, inclusiv workerul; nu o seta pentru fluxul curent. Pentru importul din link sunt suficiente variabilele deja existente în `.env.local`; cheia `service_role` și `.env.worker` nu sunt necesare.

## Verificări

```powershell
npm run typecheck
npm test
npm run build
```

Testele folosesc o bază PostgreSQL locală de test, fără datele sau cheile tale. Parserul a fost verificat și pe pagina exemplu, la data livrării. Structura sursei poate evolua; preview-ul rămâne pasul de verificare înainte de salvare.

Dacă sursa răspunde cu 403/429 sau pagina nu conține versuri identificabile, aplicația arată un mesaj și nu salvează conținut parțial. Poți reîncerca sau folosi fila Din text. Nicio pagină HTML externă nu se execută în interfața aplicației.

## Dezvoltare

Node.js >=22.14. Dependențe și versiuni fixate în `package-lock.json`.

- Parser și acces la pagina sursă: `lib/link-import/parser.ts`.
- Preview și salvare: `app/(app)/import/link-actions.ts`.
- Interfață import: `components/ImportWorkspace.tsx` și `components/ImportLinkWizard.tsx`.
- Migrare nouă: `supabase/migrations/037_v43_link_import.sql`.
- Regenerare SQL-uri de instalare: `npm run sql:package`.

`supabase/setup/INSTALL-NEW.sql` este păstrat exclusiv pentru o instalare de la zero pe o bază fără SongApp. Instrucțiunile istorice pentru worker sunt în `docs/history/v42-installation-history.md`.
